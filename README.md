## 🛠️ Инструкция по локальному запуску

Так как для сборки Docker-образа приложению требуется база данных внутри рабочего контекста, процесс локального тестирования разделен на три простых шага. Все команды выполняются из **корня** проекта.

### Шаг 1. Подготовка базы данных

Скопируйте предустановленную базу данных `tracker.db` из папки `db/` в папку с исходным кодом `src/`:

```bash
cp db/tracker.db src/

```

> *Примечание: Файл базы данных добавлен в `.gitignore` внутри папки `src/`, поэтому это действие не замусорит ваш гит-коммит.*

### Шаг 2. Сборка Docker-образа

Запустите сборку оптимизированного Docker-образа. Флаг `-f` указывает путь к Dockerfile, а точка в конце `.` задает корень проекта как контекст сборки:

```bash
docker build -t learning-go-tracker:local -f docker/Dockerfile .

```

### Шаг 3. Запуск контейнера

Запустите контейнер в фоновом режиме (`-d`) с пробросом порта `8080` на локальную машину:

```bash
docker run -d -p 8080:8080 --name tracker-test learning-go-tracker:local

```

После успешного запуска приложение станет доступно в браузере или через API по адресу:

👉 **`http://localhost:8080`**

### Полезные команды для проверки:

* **Просмотр логов приложения:** `docker logs -f tracker-test`
* **Остановка контейнера:** `docker stop tracker-test`
* **Удаление контейнера:** `docker rm tracker-test`

## 🚀 Автоматизация (CI/CD GitHub Actions)

В проекте настроен автоматический рабочий процесс (`.github/workflows/push.yaml`), который делится на два этапа:

1. **Тестирование (Lint and Test):** Запускается при любом `push` или `pull_request` в ветки `main` и `master`. Проверяет код и прогоняет Go-тесты.
2. **Сборка и Пуш (Build and Push):** Срабатывает только при создании тега версии (например, `v1.0.0`). Автоматически собирает Production-образ и отправляет его в Docker Hub под тегами `latest` и соответствующей семантической версией.
